## 2. 提案書と当方企画（v1）の差分 — ここが本改訂の核

### 差分①【重要】提供読み上げが毎配信ついてくる

v1は5分枠だけを設計していました。しかし**継続プランには提供読み上げが毎配信含まれます**。接触量で比較すると:

```
提供読み上げ：週1配信 × 26週 × 同接300 ≒ 延べ 7,800 接触（冒頭・ブランド名＋ロゴ）
5分PR枠　　：6回 × 同接300　　　　　≒ 延べ 1,800 接触（本編・製品理解）
                                          ↑ 接触"量"は読み上げが約4倍
```

**したがって「薄く広く（先方）」と「山を作る（当方）」は対立しません。**

```
提供読み上げ（毎配信・26回） → 薄く広く。ブランド名の刷り込み・認知の土台
5分PR枠（6回）              → 山。値上げ前とApple新作に寄せて購買を取る
```

この役割分担が、今回の設計上の最大の発見です。**読み上げ原稿を月ごとに差し替えられるか**が交渉の要点になります（§7）。

### 差分②【重要】プランBに単価メリットはない

先方は月20万のプランBを「おすすめ」としていますが、**1回あたり単価はA・Bとも10万円で同額**です（単価が下がるのはCの7.5万のみ）。

つまり **「プランA＋必要な月だけスポット追加（10万/回）」は、プランBと同じ単価**です。先方の売上が同じであれば断る理由は薄く、こちらは**山の月だけ回数を増やす柔軟性**を得られます。§4 の推奨はこの構成です。

### 差分③ ガジェット連動軸は先方案を採用すべき

v1は第4回以降を「ファッション相性シリーズ」で組み、ガジェット連動軸を持っていませんでした。先方案③の方が**ガジェタッチの視聴者に近い**と判断します。

- 視聴者は「ガジェット好き」であって「ファッション好き」ではない
- **Apple純正品と並べた質感比較**は、先方の目的②「純正品級の高級感 × 手頃な価格」を*証明する*唯一の見せ方で、購買に最も直結する
- デスクセットアップ／持ち物紹介はガジェタッチの既存フォーマットに乗るため、広告色が出ない

→ **第4回をガジェット連動に変更**し、ファッション連動は第5回に移します。

### 差分④ 先方のSTEP1-3と当方の6回はほぼ重なる。ただし時期の修正が必要

先方の ゲスト回 → モニター募集＋クーポン → 長期使用レビュー は、そのまま6回の骨格に載ります。ただし**モニター募集は10月までに実施しないと、最終回で「長期使用レビュー」が成立しません**（1ヶ月使用では長期と言えない）。

v1はプレゼント企画を11月に置いていましたが、**モニター募集は第4回（10月）に前倒し**します。

### 差分⑤ 先方資料にはKPI・効果測定の記載がない

クーポン利用数への言及のみです。**回別クーポン・回別UTM（§3）は当方から持ち込む必要があります。** 6ヶ月後に継続判断をするための必須要件です。

### 差分⑥ 二次利用は別料金 — 予算設計に効く

切り抜きを自社サイト・SNSで使うだけで5万/本、広告利用は10万/本。**6回全部を二次利用すると30万円の追加**です。→ 全数契約せず、**KPIの良かった回だけを選んで広告に転用**するのが正しい設計です（§4）。

## 3. ゴール設計とKPI

打合せのゴール「ガジェタッチのユーザーにブランドを知ってもらう → 買ってもらう」を、6ヶ月で追える形に分解します。

```
認知              理解               検討               購入            拡散
──────────────────────────────────────────────────────────────────────────
提供読み上げ      「Apple純正と      「自分のWatchに    値上げ前/         WSC投稿
（毎配信・26回）  並べても遜色ない」  合うのはこの色」   新作発売時に      → 二次拡散
                                                       背中を押される
──────────────────────────────────────────────────────────────────────────
常時              第1・4回           第3〜5回           第2・3回          第5〜6回
```

### KGI
6ヶ月で **ガジェタッチ経由の売上を可視化し、単発ではなく継続的に売れる導線を1本つくる**。

### KPI（各回で必ず取る5指標）

| 指標 | 取り方 |
|------|--------|
| ① コーナー同時接続 | 配信アナリティクスのピーク（先方から共有可否を要確認） |
| ② 回別クーポン利用数 | Shopifyクーポン `GT01`〜 を回ごとに発行 |
| ③ 回別URLのセッション | UTM付き短縮URL（`utm_content=ep01` 等） |
| ④ WSC新規登録・投稿数 | `campaigns` slug 単位で集計（§9） |
| ⑤ SNS二次投稿数 | 指定ハッシュタグの投稿数 |

**②③は回ごとにコードとURLを分けること。**これがないと6ヶ月後に「どの回が効いたか」がわからず、継続判断も二次利用の選定（§4）もできません。**第1回から必須**で、後付けができない唯一の項目です。

### 数字の考え方
同接300の生配信は視聴者の重複が大きく、**同じ人に何度も当てる**設計になります。これは弱点ではなく、単発PRでは作れない積み上げです。先方が「薄く広く継続」を推すのも同じ理由で、ここは思想が一致しています。したがって6回は単発の寄せ集めにせず、**次回予告で1本の線につなぐ**のが必須要件です（§6）。

## 4. プラン選定と費用試算

### 推奨：プランA ＋ 9月にスポット1回（税別 75万円）

| 項目 | 金額 | 内訳 |
|------|------|------|
| プランA × 6ヶ月 | 60万円 | 提供読み上げ毎配信 ＋ 5分PR枠 月1回 × 6 |
| 9月スポット追加 1回 | 10万円 | Apple発表週と発売週の2回を9月に置くため |
| モニター企画 1回 | 5万円 | 第4回（クーポン配布は追加費用なし） |
| 初回ゲスト出演回 | 0円 | 契約特典（通常10万円） |
| **小計** | **75万円** | |
| 二次利用（成果次第で後乗せ） | +5万〜10万/本 | §後述 |

### なぜプランBではないか

| | プランB | プランA＋スポット |
|---|---------|------------------|
| 6ヶ月総額 | 120万円（12回） | 60万＋必要分（例:70万・7回） |
| 1回単価 | 10万円 | 10万円（**同額**） |
| 回数の置き方 | 毎月2回で固定 | **山の月に寄せられる** |
| ネタの質 | 12本分の企画が必要 | 7本に集中できる |

単価が同じである以上、**Bを選ぶ理由は「毎月2回の固定枠」だけ**です。ところが今回は9月に山を作りたいので、固定より可変の方が要件に合います。加えて同接300の重複視聴環境で月2回×6ヶ月は接触過多になりやすく、5分枠のネタも12本は持ちません。

なお**認知の土台は提供読み上げ（毎配信26回）が担う**ため、5分枠を月1回に絞っても認知量は落ちません。これがAで足りる根拠です。

### 二次利用の考え方（重要）

6回全部を二次利用契約すると30万円ですが、**効果は回ごとに大きくばらつきます**。KPI（§3）で上位だった1〜2本を選んで転用するのが正しい順序です。

```
6回実施 → KPIで上位1〜2本を特定 → その回だけ二次利用 or 広告転用
                                    切り抜き二次利用  5万/本
                                    SNS広告での利用  10万/本（3ヶ月）
```

**契約時に二次利用を全数で握らないこと。**成果を見てから選べる余地を残す方が、同じ予算で効果が上がります。

### 予算に余裕がある場合の追加候補（優先順）
1. **SNS広告での利用 10万/本** — 反応の良かった回を広告に回す。最もROIが読める追加投資
2. **ライブ配信特集 20万/回** — 9月の新型発売週に当てるなら効果が最大化する。ただし5分枠×2で代替可能
3. **SNS広告用ショート動画の制作 20万/本** — 自社で制作手段があるなら不要

## 6. 5分枠の共通フォーマット

先方の5分枠は「雑談に製品紹介を織り交ぜる、広告色を抑えたフォーマット」です。**秒割りをガチガチに固定すると先方の持ち味が消える**ので、以下は台本ではなく**目安と必須項目**として渡します。

| 区間 | 秒 | 内容 | 固定度 |
|------|-----|------|--------|
| A. 導入 | 0:00–0:45 | 今日のお題を1行で | 目安 |
| B. 本編 | 0:45–3:30 | 現物を映す。**1回1メッセージ** | 自由 |
| C. 視聴者アクション | 3:30–4:30 | クーポン／URL／WSC。**コメント欄に固定** | **必須** |
| D. 次回予告 | 4:30–5:00 | 次回テーマを1行 | **必須** |

### 必須項目は C と D の2つだけ
- **C を削ると認知で終わり、購入につながりません。**
- **D がないと6回が単発の寄せ集めになります。**シリーズとして積み上げるための最重要パーツです。

### 撮影・見せ方のお願い（レギュレーションではなく依頼）
1. **手元と装着の両方を映す** — バンドは腕に乗ったときの印象が商品価値そのもの
2. **色は3本以上を並べる** — 1本だけだと「バンド1本の紹介」に見え、ブランドとして認知されない
3. **各回の「持ち帰ってほしい1行」を1つだけ**（§8に各回1行を定義）

## 7. 提供読み上げの設計（v2で新設）

延べ接触の約8割を担うにもかかわらず、最も見落とされやすい枠です。

### 基本形
> 「この番組は、Apple Watch バンドの Campagne Sélection の提供でお送りします。」＋ロゴ表示

### 提案：原稿を月ごとに差し替える

同じ原稿を26回読むより、**その月の5分枠と連動した一文を足す**方が確実に効きます。追加費用なしで交渉できる可能性が高い項目です。

| 時期 | 追加する一文の方向性 |
|------|---------------------|
| 8月 | 「Apple純正品のような高級感を、手頃な価格で」＝ブランドの基本価値 |
| 9月 | 「チタンバンドは◯月◯日から価格改定」＝値上げ前の駆け込み |
| 10月 | 「モニター募集中」＝STEP2への送客 |
| 11月 | 「プレゼント企画実施中」 |
| 12月〜1月 | 「2本目のバンドに」＝先方案②の購買文脈 |

### 交渉ポイント
- 原稿の差し替え頻度（月次 or 固定）と、その追加費用の有無 → **§12 の確認事項へ**
- ロゴ表示の秒数・サイズ・画面上の位置
- 読み上げ実績のレポート（何回の配信で読まれたか）の共有可否

## 8. 全6回 詳細企画

---

### 第1回：「なぜこのブランドを作ったのか」— 菅原社長ゲスト出演

- **時期**: 8月下旬（値上げ日の2〜3週間前）／**先方STEP1・無償特典枠**
- **目的**: 認知と信頼。「知らないブランド」から「人の顔が見えるブランド」へ
- **持ち帰ってほしい1行**: **「Apple Watchのバンドを本気で作っている日本のブランドがある」**
- **尺**: ★要確認。ゲスト出演回は5分枠と別メニュー（通常10万/回）のため、**5分より長い想定**。長く取れる場合は下記を拡張する

#### 構成（5分の場合の目安）

| 秒 | 内容 |
|-----|------|
| 0:00–0:45 | 菅原社長を紹介。**肩書きより先に「この人がこのバンドを作った人」**として出す |
| 0:45–1:45 | ブランドの成り立ち。「なぜApple Watchのバンドだったのか」を社長の言葉で |
| 1:45–3:00 | 現物。代表3ラインを実物で（FKM／レザー／**チタン**）。素材と作りの違いを触りながら |
| 3:00–3:30 | **チタンに寄せる**。「これ、来月から値上げになるんですよね？」を**ガジェタッチさんから聞いてもらう** |
| 3:30–4:30 | 視聴者アクション：クーポン `GT01` ＋専用URL。WSCは名前だけ（20秒） |
| 4:30–5:00 | 次回予告「来週のApple発表を受けて、今持ってるWatchをどうするか話します」 |

#### 設計意図
- **値上げ告知を社長本人に言わせない。**ガジェタッチさんが質問し社長が答える形にすると、「宣伝」ではなく「情報」になります。生配信の視聴者はここに敏感です。
- 初回に売り込みすぎると6回もちません。**人と思想が2/3、商品が1/3**の配分。
- WSCの紹介は20秒に留める。初回で導線を2本出すと両方薄まるため、**初回は購入に一本化**。

#### 菅原社長への事前ヒアリング項目
生配信で刺さる話は事前に引き出さないと本番で出ません。以下を伺い、ガジェタッチさんに**質問リストとして**渡します（社長の話す内容ではなく、聞く側の台本にするのがポイント）。

1. Apple Watchのバンドを作ろうと決めた瞬間の具体的なエピソード（年・場所・きっかけ）
2. 最初の試作で失敗したこと／捨てた案
3. 素材選定で譲らなかった点（特にチタン／FKM）
4. **OEMで培った技術のうち、自社ブランドに活きているもの**（先方の目的③「OEM主体からBtoCへ」に直結。ここが「純正品級の品質」の最も強い根拠になります）
5. 「他社と何が違うか」を、スペックではなく体験の言葉で1つ
6. 今回の値上げの理由（原材料／為替／製法）— **誠実に説明できる形で**
7. ユーザーに一番言われて嬉しかった感想

#### 第1〜2回をつなぐ企画：「社長への公開質問」
- 第1回終盤で「社長に聞きたいこと、コメントで募集します」と告知
- 集まった質問から3つを選び、**第2回の冒頭30秒で社長が回答**（VTRまたはコメント出演）
- 狙い：①第1回のコメント欄が動く（＝**先方にもメリット**）②第1・2回が繋がる ③「自分の質問が採用されるかも」で第2回の視聴動機になる

制作コストがほぼゼロで先方にも利があるのが要点です。PR企画は片側だけが得をする設計だと続きません。

## 9. Watch Style Club（自社基盤）との接続

ガジェタッチの視聴者は借り物ですが、**WSCに登録された人は自社の資産**になります。6ヶ月の投資の本当の回収先はここです。

### 既存実装で足りるもの（新規開発不要）

| 用途 | 使う既存機能 | 状況 |
|------|-------------|------|
| 応募受付・集計 | `campaigns` ＋ `lib/campaign.ts` | 実装済み |
| SNS拡散 | `lib/share.ts`（X/Facebook/LINE共有インテント、OGP、共通ハッシュタグ） | 実装済み |
| 参加賞ポイント | Point Engine（`lib/points.ts`） | 実装済み |
| ミッション化 | Mission Engine（`lib/missions.ts`、`group` は汎用文字列で拡張可） | 実装済み |
| 購入者判定 | Shopify購入証明連携（`lib/verified-purchases.ts`） | 実装済み |

### 準備が必要なもの

1. **キャンペーンレコード** — `campaigns` に slug `gadgetouch-2026` を追加（`supabase/seed.sql` の `opening-2026-08` と同形式）。第5回の応募期間を `starts_at` / `ends_at` に設定
2. **回別UTM着地URL** — 例 `?utm_source=gadgetouch&utm_medium=live&utm_campaign=gt2026&utm_content=ep01`。**第1回から必須**
3. **Shopifyクーポン `GT01`〜`GT06`** — 回ごとに分けて回別の売上寄与を測る。割引率は揃え、回による有利不利を作らない（比較可能性の確保）
4. **モニター用の受け皿** — 第4回のモニター応募をWSC経由にする場合、応募フォームまたは既存campaignの流用を検討
5. **ミッション定義の追加（任意）** — `group='campaign'` のレコード追加のみでアプリ内導線が作れる（コード変更不要）

### 既知の制約
`mission_definitions.visibility` の `'campaign_only'` は**判定ロジックが未実装**で、現状は安全側で非表示になります（`lib/missions.ts` の `isMissionVisible`）。キャンペーン限定ミッションを出すなら事前実装が必要ですが、`'logged_in'` で運用する回避策もあります。

## 10. 提供物とレギュレーション

企画を通すには、**先方の手間を最小化した状態で渡す**ことが決定的です。

### 毎回渡すもの（各回の1週間前まで）
1. **進行メモ**（§6の必須項目＋話す論点の箇条書き。**読み上げ台本にしない** — 先方の持ち味である雑談フォーマットを殺さないため）

## 11. リスクと対応

| リスク | 影響 | 対応 |
|--------|------|------|
| 値上げ日が9月以降にずれる | 第1・2回の駆け込み訴求が空振り | ②のラストコールを③に移設。①はブランド訴求のみで成立 |
| Apple Watchが発表されない／マイナーチェンジのみ | ②③の前提が崩れる | ③を「買い替えずに新しくする」に差し替え。バンド商材には本質的なテーマなので致命傷ではない |
| 純正比較（第4回）が「純正より安い」だけの印象になる | ブランド価値の毀損 | 価格だけでなく**OEMで培った技術**（社長ヒアリング項目4）を根拠として必ず添える |
| モニターの反応が芳しくない | 第6回の長期レビューが成立しない | モニターは3〜5名に絞り、**事前に人選の質を確保**。中間フォローを11月に入れる |
| プレゼント企画の応募が集まらない | 第5回が不発 | 応募3ステップ厳守＋**参加賞を全員に** |
| 生配信で誤った価格・仕様が伝わる | 信用問題 | テロップ素材を必ず用意し、口頭情報に依存させない |
| 6回が単発の寄せ集めになる | 積み上げが効かない | 次回予告を**必須項目**として毎回明記（§6） |
| 効果測定ができず継続判断も二次利用選定もできない | 6ヶ月が無駄になる | 回別クーポン・回別UTMを**第1回から**。後付け不可 |
| 提供読み上げが形骸化する（同じ原稿を26回） | 最大の接触枠が死ぬ | 原稿の月次差し替えを契約段階で握る（§7） |
